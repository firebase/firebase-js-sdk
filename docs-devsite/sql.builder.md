# Builder interface
Terminal `PromiseLike` builder interface providing execution modifiers (`throwOnError`<!-- -->, `stripNulls`<!-- -->, `setHeader`<!-- -->, `retry`<!-- -->) and static result-type overrides (`returns`<!-- -->, `overrideTypes`<!-- -->).

Lazy execution and non-cached re-execution: no HTTP request is issued until the builder is `await`<!-- -->ed or `.then()` is called. Each `await` or `.then()` call sends a new HTTP request built from the builder's current state; results are never cached. Awaiting the same builder twice (sequentially or via `Promise.all([q, q])`<!-- -->) executes it twice—harmless for reads, but it duplicates writes for `insert()`<!-- -->, `upsert()`<!-- -->, `update()`<!-- -->, `delete()`<!-- -->, and write `rpc()` builders. Await each mutation builder at most once.

Builder progression: `Builder` is the base interface of [TransformBuilder](./sql.transformbuilder.md#transformbuilder_interface) and [FilterBuilder](./sql.filterbuilder.md#filterbuilder_interface)<!-- -->. Once a chain narrows to `Builder` (via `.single()`<!-- -->, `.maybeSingle()`<!-- -->, `.csv()`<!-- -->, `.geojson()`<!-- -->, `.explain()`<!-- -->, `.overrideTypes()`<!-- -->, or `Builder.returns()`<!-- -->), filter and transform methods are no longer available—only `Builder` methods and `await` remain.

<b>Signature:</b>

```typescript
export interface Builder<T, ThrowOnError extends boolean = false> extends PromiseLike<ThrowOnError extends true ? OperationSuccess<T> : OperationResult<T>> 
```

## Builder.overrideTypes()

Overrides or deep-merges the static TypeScript type of `result.data` at compile time without performing runtime validation.

When to use: partially overriding or refining specific fields (such as narrowing a `jsonb` column or a status literal union) on an already-typed builder via default `{ merge: true }` deep-merging—for example, chaining `.returns<EventRow[]>().overrideTypes<Array<{ metadata: EventMetadata }>>()` preserves every other `EventRow` property while refining `metadata`<!-- -->. When specifying the complete row, array, or scalar type from scratch, prefer [.returns()](./sql.builder.md#builderreturns) (or [TransformBuilder.returns()](./sql.transformbuilder.md#transformbuilderreturns)<!-- -->) so you do not need to pass `{ merge: false }`<!-- -->.

Do not use mid-chain before `.eq()`<!-- -->, `.order()`<!-- -->, `.limit()`<!-- -->, or `.single()`<!-- -->—`overrideTypes()` returns a base [Builder](./sql.builder.md#builder_interface) that does not expose filter or transform methods. Always place `overrideTypes()` after filters, transforms, and [.single()](./sql.transformbuilder.md#transformbuildersingle) / [.maybeSingle()](./sql.transformbuilder.md#transformbuildermaybesingle)<!-- -->.

Do not chain after [.explain()](./sql.transformbuilder.md#transformbuilderexplain)<!-- -->—`explain()` returns a union of array and `string` builders that rejects both array and non-array overrides; narrow `res.data` with `typeof res.data === 'string'` instead.

Match array cardinality: pass `Array<PartialRow>` for list queries and `PartialRow` (non-array) after `.single()` or `.maybeSingle()` (passing an array after `.single()`<!-- -->, or a non-array on a list query, produces a compile-time `{ Error: 'Type mismatch: ...' }` type). When called after `.maybeSingle()`<!-- -->, `| null` is preserved automatically.

Choosing `Options` (default `{ merge: true }` vs. `{ merge: false }`<!-- -->): by default (`{ merge: true }`<!-- -->), [MergeDeep](./sql.md#mergedeep) deep-merges `NewResult` onto `T` while preserving existing properties and any `[K: string]` index signature on `T`<!-- -->. On an untyped table query (`T = Array<Record<string, unknown>>`<!-- -->), `{ merge: true }` therefore retains `[K: string]: unknown` alongside your overridden fields (and if `NewResult` itself carries a `[key: string]` index signature, [ExplicitKeys](./sql.md#explicitkeys) collapses merged explicit keys). Pass `{ merge: false }` to discard `T` completely instead of merging, or use [.returns()](./sql.builder.md#builderreturns) for full-type replacement with a single type parameter. On direct [sql.rpc()](./sql.firebasesql.md#firebasesqlrpc) chains where `T` is `unknown`<!-- -->, `{ merge: true }` short-circuits directly to `NewResult`<!-- -->.

Behavior and side effects: compile-time type cast only; performs no network I/O or runtime schema parsing.

<b>Signature:</b>

```typescript
overrideTypes<NewResult, Options extends {
        merge?: boolean | undefined;
    } = {
        merge: true;
    }>(): Builder<IsValidResultOverride<T, NewResult, false, false> extends true ? ContainsNull<T> extends true ? MergePartialResult<NewResult, NonNullable<T>, Options> | null : MergePartialResult<NewResult, T, Options> : CheckMatchingArrayTypes<T, NewResult>, ThrowOnError>;
```
<b>Returns:</b>

[Builder](./sql.builder.md#builder_interface)<!-- -->&lt;[IsValidResultOverride](./sql.md#isvalidresultoverride)<!-- -->&lt;T, NewResult, false, false&gt; extends true ? [ContainsNull](./sql.md#containsnull)<!-- -->&lt;T&gt; extends true ? [MergePartialResult](./sql.md#mergepartialresult)<!-- -->&lt;NewResult, NonNullable&lt;T&gt;, Options&gt; \| null : [MergePartialResult](./sql.md#mergepartialresult)<!-- -->&lt;NewResult, T, Options&gt; : [CheckMatchingArrayTypes](./sql.md#checkmatchingarraytypes)<!-- -->&lt;T, NewResult&gt;, ThrowOnError&gt;

This [Builder](./sql.builder.md#builder_interface) with `data` statically typed according to `NewResult` and `Options`<!-- -->.

### Example 1

Partially refine a `jsonb` `metadata` column on a typed `EventRow[]` query (`{ merge: true }` default):

```ts
interface EventRow {
  id: string;
  code: string;
  title: string;
  metadata: unknown;
}

interface EventMetadata {
  track: 'backend' | 'web' | 'mobile';
  level: 100 | 200 | 300;
}

const res = await sql
  .from('events')
  .select('id, code, title, metadata')
  .eq('status', 'published')
  .returns<EventRow[]>()
  .overrideTypes<Array<{ metadata: EventMetadata }>>();

if (res.success) {
  // id, code, and title are preserved from EventRow; metadata is narrowed to EventMetadata
  console.log(res.data[0]?.title, res.data[0]?.metadata.track);
}

```

### Example 2

Replace an untyped table result completely using `{ merge: false }` (equivalent to `.returns<Venue[]>()`<!-- -->):

```ts
interface Venue {
  id: string;
  slug: string;
  name: string;
}

const res = await sql
  .from('venues')
  .select('id, slug, name')

```

## Builder.retry()

Enables or disables automatic transient-failure retries for `GET` and `HEAD` HTTP requests on this builder.

Default behavior (`enabled = true`<!-- -->): retries are enabled by default on every builder, but only execute for `GET` and `HEAD` requests (such as `select()`<!-- -->, `rpc(..., { get: true })`<!-- -->, and `rpc(..., { head: true })` when `params` contains no plain object values or arrays of objects; primitive array arguments like `{ ids: [1, 2] }` stay `HEAD` and are retried, whereas plain objects or arrays containing objects fall back to `POST` and are not retried).

Requests using `POST`<!-- -->, `PATCH`<!-- -->, or `DELETE` (including `insert()`<!-- -->, `upsert()`<!-- -->, `update()`<!-- -->, `delete()`<!-- -->, and `POST`<!-- -->-mode `rpc()`<!-- -->) and requests cancelled via `AbortSignal` are never retried even when `enabled` is `true`<!-- -->.

Eligible requests retry up to `3` times (`4` total attempts) on network `fetch` rejections or HTTP status `503` / `520`<!-- -->, backing off exponentially (`1s`<!-- -->, `2s`<!-- -->, `4s`<!-- -->, or honoring the server's `Retry-After` header on `503` / `520`<!-- -->) and sending an `X-Retry-Count` header on retry attempts. Note that Firebase Auth `getToken()` rejections on `GET` or `HEAD` surface as `fetch` rejections and are retried with the same `1s`<!-- -->, `2s`<!-- -->, `4s` backoff before failing.

Calling `retry(false)` disables PostgREST backoff retries on `503`<!-- -->/`520`<!-- -->/network errors, whereas the Firebase transport's single HTTP `401` Auth token refresh-and-retry remains active whenever Firebase Auth is attached.

When to use: pass `false` on latency-sensitive `select()` queries where failing fast on the first transient error is preferred over waiting through backoff delays.

<b>Signature:</b>

```typescript
retry(enabled: boolean): this;
```

#### Parameters

|  Parameter | Type | Description |
|  --- | --- | --- |
|  enabled | boolean | <code>false</code> to disable automatic retries for this request; <code>true</code> to re-enable default <code>GET</code>/<code>HEAD</code> retry behavior. |

<b>Returns:</b>

this

This builder for continued chaining.

### Example

Fail fast without backoff retries on an interactive autocomplete query:

```ts
const res = await sql
  .from('events')
  .select('id, code, title')
  .ilike('title', 'fire%')
  .limit(5)
  .retry(false);

```

## Builder.returns()

Replaces the static TypeScript type of `result.data` with `NewResult` at compile time without performing runtime validation.

When to use: assigning a full static row, array, or scalar payload type on a terminal [Builder](./sql.builder.md#builder_interface) (such as after [.single()](./sql.transformbuilder.md#transformbuildersingle)<!-- -->, [.maybeSingle()](./sql.transformbuilder.md#transformbuildermaybesingle)<!-- -->, or [.geojson()](./sql.transformbuilder.md#transformbuildergeojson)<!-- -->; on [FilterBuilder](./sql.filterbuilder.md#filterbuilder_interface) or [TransformBuilder](./sql.transformbuilder.md#transformbuilder_interface) chains, [TransformBuilder.returns()](./sql.transformbuilder.md#transformbuilderreturns) provides the same full-type replacement while keeping transform methods available). Unlike [.overrideTypes()](./sql.builder.md#builderoverridetypes)<!-- -->, `returns<NewResult>()` replaces the untyped `Record<string, unknown>` base type directly with a single type parameter—no `{ merge: false }` option is needed to shed `[K: string]: unknown`<!-- -->. When you instead want to partially override or refine specific fields on an already-typed builder while keeping all other properties intact, use [Builder.overrideTypes()](./sql.builder.md#builderoverridetypes)<!-- -->.

Do not chain after [.explain()](./sql.transformbuilder.md#transformbuilderexplain)<!-- -->—`explain()` returns a union of array and `string` builders that rejects both array and non-array overrides; narrow `res.data` with `typeof res.data === 'string'` instead.

Match array cardinality: pass `MyRow[]` for array results and `MyRow` (non-array) after `.single()` or `.maybeSingle()` (enforced at compile time via [CheckMatchingArrayTypes](./sql.md#checkmatchingarraytypes)<!-- -->). When called after `.maybeSingle()`<!-- -->, `| null` is preserved automatically (`MyRow | null`<!-- -->).

Behavior and side effects: compile-time type cast only; performs no network I/O or runtime schema parsing, and preserves `ThrowOnError`<!-- -->.

<b>Signature:</b>

```typescript
returns<NewResult>(): Builder<CheckMatchingArrayTypes<T, NewResult>, ThrowOnError>;
```
<b>Returns:</b>

[Builder](./sql.builder.md#builder_interface)<!-- -->&lt;[CheckMatchingArrayTypes](./sql.md#checkmatchingarraytypes)<!-- -->&lt;T, NewResult&gt;, ThrowOnError&gt;

This [Builder](./sql.builder.md#builder_interface) with `data` statically typed as `CheckMatchingArrayTypes<T, NewResult>`<!-- -->.

### Example 1

Assign a full `Venue` type after `.single()`<!-- -->:

## Builder.setHeader()

Sets a custom HTTP header on this single request, overriding any client-level header of the same name configured via [FirebaseSql.setHeaders()](./sql.firebasesql.md#firebasesqlsetheaders)<!-- -->.

When to use: attaching per-request correlation, tracing, or custom application headers (see [FirebaseSql.setHeaders()](./sql.firebasesql.md#firebasesqlsetheaders) for client-wide static headers).

Do not use for authentication, impersonation, App Check, Firebase telemetry/routing, or PostgREST-managed headers—passing any protected header name (matched case-insensitively after trimming: `'authorization'`<!-- -->, `'x-firebase-auth-impersonate'`<!-- -->, `'x-firebase-auth-token'`<!-- -->, `'x-firebase-appcheck'`<!-- -->, `'x-goog-api-client'`<!-- -->, `'x-client-version'`<!-- -->, `'x-firebase-gmpid'`<!-- -->, `'x-firebase-client'`<!-- -->, `'x-firebase-client-log-type'`<!-- -->, `'x-goog-request-params'`<!-- -->, `'x-firebase-sqlconnect-affinity'`<!-- -->, `'accept-profile'`<!-- -->, `'content-profile'`<!-- -->, `'x-retry-count'`<!-- -->, `'prefer'`<!-- -->, `'accept'`<!-- -->, `'content-type'`<!-- -->, `'range'`<!-- -->, `'range-unit'`<!-- -->) synchronously throws a [FirebaseSqlError](./sql.firebasesqlerror.md#firebasesqlerror_class)<!-- -->. Firebase Auth and App Check tokens are injected automatically by the SDK transport.

Behavior and side effects: clones this builder's internal `Headers` map, calls `Headers.set(name, value)`<!-- -->, and returns `this` without network I/O.

## Builder.stripNulls()

Instructs PostgREST to omit keys whose value is `null` from returned JSON row objects (`Accept: application/vnd.pgrst.array+json;nulls=stripped` or `application/vnd.pgrst.object+json;nulls=stripped`<!-- -->).

When to use: reducing JSON payload size when rows contain sparse nullable columns (such as `events.venue_id` or `registrations.checked_in_at`<!-- -->). Stripped keys become `undefined` at runtime, so declare optional properties (`prop?: Type`<!-- -->) in your [.returns()](./sql.builder.md#builderreturns) or [.overrideTypes()](./sql.builder.md#builderoverridetypes) interface.

Do not use after [.csv()](./sql.transformbuilder.md#transformbuildercsv)<!-- -->—calling `.csv().stripNulls()` throws a synchronous `Error('stripNulls() cannot be used with csv()')`<!-- -->. Calling `.stripNulls()` before `.csv()`<!-- -->, `.geojson()`<!-- -->, or `.explain()` has no effect because `nulls=stripped` is only applied when `Accept` is JSON or `application/vnd.pgrst.object+json`<!-- -->.

Preconditions: requires PostgREST 11.2.0 or newer on the backend.

<b>Signature:</b>

```typescript
stripNulls(): this;
```
<b>Returns:</b>

this

This builder for continued chaining.

#### Exceptions

`Error` synchronously if `Accept` is already `'text/csv'` (after calling [.csv()](./sql.transformbuilder.md#transformbuildercsv)<!-- -->).

### Example

Omit `null` properties from returned registration JSON objects:

```ts
interface SparseRegistration {
  id: string;
  attendee_email: string;
  checked_in_at?: string;
}

const res = await sql
  .from('registrations')
  .select('id, attendee_email, checked_in_at')
  .stripNulls()
  .returns<SparseRegistration[]>();

```

## Builder.throwOnError()

Configures this builder to reject its promise with a [FirebaseSqlError](./sql.firebasesqlerror.md#firebasesqlerror_class) on HTTP, PostgREST, platform, or network failures instead of resolving an [OperationFailure](./sql.operationfailure.md#operationfailure_interface)<!-- -->, narrowing the resolved envelope to [OperationSuccess](./sql.operationsuccess.md#operationsuccess_interface)<!-- -->.

When to use: `try / catch` workflows, helper functions, or data-fetching hooks (such as React Query or SWR) that expect failed promises to reject.

Do not use in code paths that prefer exhaustive discriminated-union checking (`if (!res.success)`<!-- -->) without `try / catch`<!-- -->; omit `throwOnError()` to receive [OperationResult](./sql.md#operationresult)<!-- -->. Note that a `serviceConfig.schemaName` containing invalid HTTP header characters always rejects with a `TypeError` when setting the profile header, regardless of `throwOnError()`<!-- -->.

Behavior and side effects: even with `throwOnError()`<!-- -->, awaiting the builder resolves to `{ success: true, data: T, count, error: null, status, statusText }` ([OperationSuccess](./sql.operationsuccess.md#operationsuccess_interface)<!-- -->), not raw `T`<!-- -->—always destructure `const { data } = await query.throwOnError()`<!-- -->. Mutates this builder's error-handling flag in place without network I/O. Can be chained at any stage (`FilterBuilder`<!-- -->, `TransformBuilder`<!-- -->, or `Builder`<!-- -->), and `ThrowOnError = true` is preserved across `.select()`<!-- -->, `.single()`<!-- -->, `.maybeSingle()`<!-- -->, `.returns()`<!-- -->, and `.overrideTypes()`<!-- -->.

<b>Signature:</b>

```typescript
throwOnError(): Builder<T, true>;
```
<b>Returns:</b>

[Builder](./sql.builder.md#builder_interface)<!-- -->&lt;T, true&gt;

This builder narrowed to `ThrowOnError = true` (resolving to [OperationSuccess](./sql.operationsuccess.md#operationsuccess_interface) or rejecting with [FirebaseSqlError](./sql.firebasesqlerror.md#firebasesqlerror_class)<!-- -->).

### Example

Destructure `{ data }` from `OperationSuccess` inside `try / catch` with `throwOnError()`<!-- -->:

```ts
import { FirebaseSqlError } from 'firebase/sql';

try {
  const { data } = await sql
    .from('venues')
    .select('id, name, city')
    .eq('slug', 'moscone-west')
    .single()
    .returns<{ id: string; name: string; city: string }>()
    .throwOnError();

  console.log(data.name);
} catch (err) {
  if (err instanceof FirebaseSqlError) {
    console.error(err.category, err.code, err.message);
  }
}

```
