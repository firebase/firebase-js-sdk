# FilterBuilder interface
Lazy PostgREST filter builder returned by [QueryBuilder](./sql.querybuilder.md#querybuilder_interface) verbs, [FirebaseSql.rpc()](./sql.firebasesql.md#firebasesqlrpc)<!-- -->, and [TransformBuilder.select()](./sql.transformbuilder.md#transformbuilderselect)<!-- -->.

Builder progression: extends [TransformBuilder](./sql.transformbuilder.md#transformbuilder_interface) (and [Builder](./sql.builder.md#builder_interface) / `PromiseLike`<!-- -->). Chaining multiple filter methods combines predicates with logical `AND` in the outgoing URL query string (use [.or()](./sql.filterbuilder.md#filterbuilderor) for logical `OR`<!-- -->).

Value serialization guardrails (`Date`<!-- -->, `undefined`<!-- -->, and `null`<!-- -->): never pass a raw `Date` object to filter methods—URL parameter string interpolation invokes `Date.prototype.toString()` (for example, `'Thu Jan 01 2026 ... GMT+0000 (...)'`<!-- -->), which PostgreSQL rejects with SQLSTATE `'22007'` or `'22023'` depending on the runtime time zone; always pass ISO-8601 strings via `date.toISOString()`<!-- -->. Methods typed with `value: unknown` (`neq`<!-- -->, `gt`<!-- -->, `gte`<!-- -->, `lt`<!-- -->, `lte`<!-- -->, `isDistinct`<!-- -->, `not`<!-- -->, `filter`<!-- -->, and array elements of `in`<!-- -->/`notIn`<!-- -->) accept `undefined` or `null` at compile time and interpolate the literal text `'undefined'` or `'null'` into the URL; always guard optional filter inputs with `if (value !== undefined)` and use [.is(column, null)](./sql.filterbuilder.md#filterbuilderis) or [.not(column, 'is', null)](./sql.filterbuilder.md#filterbuildernot) for SQL `NULL` checks.

Embedded columns and reserved PostgREST parameter names: filtering a dot-qualified embedded column (such as `'venues.city'`<!-- -->) filters only the embedded resource—parent rows are still returned with the embedded property set to `null` or `[]` unless the relation is selected with `!inner` in `select()`<!-- -->. Also note that bare column names matching reserved PostgREST query parameters (`select`<!-- -->, `order`<!-- -->, `limit`<!-- -->, `offset`<!-- -->, `or`<!-- -->, `and`<!-- -->, `columns`<!-- -->, `on_conflict`<!-- -->) collide with PostgREST URL directives (for example, `eq('limit', 1)` is parsed as `limit` rather than a column filter).

Mutability and non-cached execution: filter methods mutate the current `FilterBuilder` instance in place and return `this`<!-- -->—do not branch two conflicting filter chains off the same `FilterBuilder` variable (branch from [sql.from(table)](./sql.firebasesql.md#firebasesqlfrom) instead). Each `await` or `.then()` call sends a new HTTP request built from the builder's current state; results are not cached. Awaiting the same builder twice (sequentially or via `Promise.all([q, q])`<!-- -->) executes it twice—harmless for reads, but it duplicates writes for `insert()`<!-- -->, `upsert()`<!-- -->, `update()`<!-- -->, `delete()`<!-- -->, and write `rpc()` builders. Await each mutation builder at most once.

## FilterBuilder.containedBy()

Filters array, `jsonb`<!-- -->, or range `column` values that are completely contained within `value` (`?column=cd.<value>`<!-- -->, PostgreSQL `<@` operator).

When to use: on range columns (`schedule tstzrange`<!-- -->), pass a bounding window string (`'[2026-10-15T00:00:00Z,2026-10-16T00:00:00Z)'`<!-- -->) to find events scheduled entirely inside that window (use [FilterBuilder.overlaps()](./sql.filterbuilder.md#filterbuilderoverlaps) for partial overlap, or [FilterBuilder.contains()](./sql.filterbuilder.md#filterbuildercontains) for `@>` superset containment). On array columns (`tags text[]`<!-- -->), pass a superset JS array so only rows whose elements are a subset of `value` match. ## FilterBuilder.eq()

Filters rows where `column` equals `value` (`?column=eq.<value>`<!-- -->).

When to use: exact equality matching on non-null strings, numbers, UUIDs, or booleans (see [FilterBuilder.match()](./sql.filterbuilder.md#filterbuildermatch) for multi-column object equality). For `jsonb` columns, use double-arrow `->>` (`'metadata->>track'`<!-- -->) when comparing strings, and single-arrow `->` (`'metadata->level'`<!-- -->) when comparing numbers or booleans (comparing a string against `->` fails with PostgreSQL `'22P02'`<!-- -->).

## FilterBuilder.overlaps()

Filters PostgreSQL array or range `column` values that share at least one element or point in common with `value` (`?column=ov.<value>`<!-- -->, PostgreSQL `&&` operator).

When to use: on array columns (`tags text[]`<!-- -->), match rows tagged with any tag in `value` (logical `OR` across tags; use [FilterBuilder.contains()](./sql.filterbuilder.md#filterbuildercontains) when every tag in `value` must be present). On range columns (`schedule tstzrange`<!-- -->), detect schedule conflicts or find events overlapping a time window.

Do not use on `jsonb` columns—PostgreSQL's `&&` operator is defined on arrays and ranges, not `jsonb` (use [FilterBuilder.contains()](./sql.filterbuilder.md#filterbuildercontains) for `jsonb`<!-- -->).

Behavior and side effects: serializes strings verbatim (for ranges or pre-quoted PostgreSQL array literals such as `'{"cloud, sql","ai"}'`<!-- -->) and JS arrays via unquoted comma-joining `{a,b}` (JS array elements are never quoted—do not pass JS array elements containing `,`<!-- -->, `"`<!-- -->, `{`<!-- -->, `}`<!-- -->, or leading/trailing whitespace), mutating URL query parameters in place without network I/O.

<b>Signature:</b>

```typescript

```

#### Parameters

|  Parameter | Type | Description |
|  --- | --- | --- |
|  column | string | PostgreSQL array (<code>text[]</code>) or range (<code>tstzrange</code>) column name. |
|  value | string \| readonly unknown\[\] | JS array of simple candidate elements (for SQL arrays) or PostgreSQL range/array literal string. |

<b>Returns:</b>

this

This [FilterBuilder](./sql.filterbuilder.md#filterbuilder_interface) for continued chaining.

### Example


## FilterBuilder.throwOnError()

Switches this builder into throwing mode so awaiting it rejects with [FirebaseSqlError](./sql.firebasesqlerror.md#firebasesqlerror_class) on failure instead of resolving to [OperationFailure](./sql.operationfailure.md#operationfailure_interface)<!-- -->, while preserving [FilterBuilder](./sql.filterbuilder.md#filterbuilder_interface) chaining. See [Builder.throwOnError()](./sql.builder.md#builderthrowonerror)<!-- -->.

<b>Signature:</b>

```typescript
throwOnError(): FilterBuilder<T, Method, true>;
```
<b>Returns:</b>

[FilterBuilder](./sql.filterbuilder.md#filterbuilder_interface)<!-- -->&lt;T, Method, true&gt;

This [FilterBuilder](./sql.filterbuilder.md#filterbuilder_interface) narrowed to `ThrowOnError = true` (resolving to [OperationSuccess](./sql.operationsuccess.md#operationsuccess_interface) when awaited).

### Example

Enable throwing mode early in a filter chain:

```ts
const { data } = await sql
  .from('events')
  .select('id, code, title')
  .throwOnError()
  .eq('status', 'published')
  .overrideTypes<Array<{ id: string; code: string; title: string }>, { merge: false }>();

```

### Example

Compose multiple `AND` predicates on a `FilterBuilder` before ordering and typing:

```ts
interface PublishedEvent {
  id: string;
  code: string;
  title: string;
  ticket_price: number;
}

const res = await sql
  .from('events')
  .select('id, code, title, ticket_price')
  .eq('status', 'published')
  .lte('ticket_price', 150)
  .contains('tags', ['firebase'])
  .order('ticket_price', { ascending: true })
  .overrideTypes<PublishedEvent[], { merge: false }>();

```
