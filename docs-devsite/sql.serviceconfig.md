# ServiceConfig interface
Connection and routing configuration for a [FirebaseSql](./sql.firebasesql.md#firebasesql_class) service client instance initialized via [getSql()](./sql.md#getsql_b956f3d)<!-- -->.

Passed to [getSql()](./sql.md#getsql_b956f3d)<!-- -->, which validates `serviceId`<!-- -->, `location`<!-- -->, and `port`<!-- -->, creates a shallow frozen copy, and resolves the PostgREST endpoint URL as `{http|https}://{host}[:{port}]/v1/projects/{projectId}/locations/{location}/services/{serviceId}/postgrest`<!-- -->.

Instance caching and HTTP headers: [getSql()](./sql.md#getsql_b956f3d) deduplicates instances by `(app, resolvedEndpointUrl, schemaName)`<!-- -->. Use [FirebaseSql.setHeaders()](./sql.firebasesql.md#firebasesqlsetheaders) to configure client-wide static headers while [FirebaseSql.mutable](./sql.firebasesql.md#firebasesqlmutable) is `true`<!-- -->, and use [Builder.setHeader()](./sql.builder.md#buildersetheader) for per-request header overrides. See [getSql()](./sql.md#getsql_b956f3d) for client initialization and error rules.

<b>Signature:</b>

## ServiceConfig.host

Custom endpoint hostname (without protocol or path) overriding the default Firebase SQL service host.

Defaults to `'firebasedataconnect.googleapis.com'`<!-- -->. Must be a bare hostname (optionally `host:port`<!-- -->) with no scheme or path. Only values rejected by the WHATWG `URL` parser when prefixed with `https://` (such as `''`<!-- -->) cause [getSql()](./sql.md#getsql_b956f3d) to throw a `TypeError`<!-- -->; passing a scheme or path is not rejected and silently produces a wrong endpoint (for example, `'http://example.com'` resolves to hostname `'http'`<!-- -->, and any path segment is overwritten).

<b>Signature:</b>

```typescript
host?: string | undefined;
```

## ServiceConfig.location

Non-empty Google Cloud region hosting the Firebase SQL service (for example, `'us-central1'`<!-- -->).

Required. Passing an empty string causes [getSql()](./sql.md#getsql_b956f3d) to throw [FirebaseSqlError](./sql.firebasesqlerror.md#firebasesqlerror_class) (`invalid-argument`<!-- -->). Percent-encoded when constructing the `/locations/{location}/` URL path.

<b>Signature:</b>

```typescript
location: string;
```

## ServiceConfig.port

Custom TCP port number appended to the resolved service endpoint URL.

Defaults to `undefined`<!-- -->. When provided, must be an integer between `1` and `65535` inclusive; non-integers or out-of-range values cause [getSql()](./sql.md#getsql_b956f3d) to throw [FirebaseSqlError](./sql.firebasesqlerror.md#firebasesqlerror_class) (`invalid-argument`<!-- -->).

<b>Signature:</b>

```typescript
port?: number | undefined;
```

## ServiceConfig.schemaName

Target PostgreSQL schema exposed by PostgREST (for example, `'analytics'`<!-- -->).

Defaults to `undefined`<!-- -->. When specified, sends `Accept-Profile: <schemaName>` on `GET` and `HEAD` requests and `Content-Profile: <schemaName>` on `POST`<!-- -->, `PATCH`<!-- -->, and `DELETE` mutations. Omitting `schemaName` (or passing `undefined`<!-- -->) omits profile headers and uses the server's default exposed schema, so specifying `'public'` is unnecessary when `'public'` is the default schema.

Do not pass an empty string `''`<!-- -->—it sends an empty profile header that PostgREST rejects with HTTP `406` (`'PGRST106'`<!-- -->). Must be a valid HTTP header value (Latin-1 characters with no CR or LF); otherwise awaiting any builder on the client rejects with a `TypeError` when setting the profile header. Note that omitting `schemaName` and passing an explicit `schemaName` string produce distinct cached [FirebaseSql](./sql.firebasesql.md#firebasesql_class) instances.

<b>Signature:</b>

```typescript
schemaName?: string | undefined;
```

## ServiceConfig.serviceId

Non-empty Firebase SQL service identifier within the Firebase project (for example, `'events-db'`<!-- -->).

Required. Passing an empty string causes [getSql()](./sql.md#getsql_b956f3d) to throw [FirebaseSqlError](./sql.firebasesqlerror.md#firebasesqlerror_class) (`invalid-argument`<!-- -->). Percent-encoded when constructing the `/services/{serviceId}/postgrest` URL path.

<b>Signature:</b>

```typescript
serviceId: string;
```

## ServiceConfig.sslEnabled

Controls whether requests use `https:` (`true` or `undefined`<!-- -->) or `http:` (`false`<!-- -->).

Defaults to `true`<!-- -->. Omitting `sslEnabled` and setting `sslEnabled: true` resolve to the same `https:` endpoint and share the same cached [FirebaseSql](./sql.firebasesql.md#firebasesql_class) instance.

<b>Signature:</b>

```typescript
sslEnabled?: boolean | undefined;
```

### Example 1

Configure a `ServiceConfig` using the default schema:

```ts
import type { ServiceConfig } from 'firebase/sql';

const serviceConfig: ServiceConfig = {
  serviceId: 'events-db',
  location: 'us-central1'
};

```

### Example 2

Configure a `ServiceConfig` targeting a non-default PostgreSQL schema:

```ts
import type { ServiceConfig } from 'firebase/sql';

const analyticsServiceConfig: ServiceConfig = {
  serviceId: 'events-db',
  location: 'us-central1',
  schemaName: 'analytics'
};

```
